# 移动端 UX 优化开发文档

> 版本 1.0 · 2026-11-07
> 对象：`app/lib/ui/shell.dart` 中的 `_MobileShell`（Flutter / Android）
> 范围：只改移动端信息架构与交互，不动引擎（`lib/core/*`）、不动桌面三栏、不新增依赖

---

## 0. 评审依据与限制

| 项 | 说明 |
| --- | --- |
| 依据 | 通读 `app/lib/ui/shell.dart`(1594 行)、`widgets.dart`、`app_state.dart`、`theme.dart`、`docs/GUI_DESIGN.md`；另有一张真机截图（登录弹窗报错） |
| 未做 | **本机没有 Flutter SDK，无法编译、无法录屏**。除登录弹窗外，其它界面未实际渲染 |
| 结论强度 | 信息架构与交互结论来自代码，可靠；像素级视觉结论需要真机复核 |
| 不做 | 不改 `core/`、不改接口、不做视觉方向重塑，沿用现有 token 与状态色 |

## 1. 一句话结论

**桌面版是「队列 + 详情 + 运行面板」，移动版只剩「列表 + 开始/停止」。**

手机端把用户最需要的三件事删掉了：**还要跑多久、现在跑到哪一节、扫描失败后怎么恢复**。这不是"不好看"，是核心任务（挂机 5–8 分钟/节、75 节要跑十几小时）在移动端没有闭环——用户只能反复拉开日志抽屉确认它没死。

---

## 2. 现状对照：移动端缺了什么

| 能力 | 桌面 | 移动 | 后果 |
| --- | --- | --- | --- |
| 当前节倒计时 / 心跳次数 | 右栏 `_CurrentCard`（966–995 行） | **无** | 挂机时唯一的安心反馈缺失 |
| 队列剩余时间估算 | 底栏 `_StatusBar`（1084 行） | **无** | 不知道还要不要盯着 |
| 失败数 / 跳过数 | 底栏 | **无** | 失败被静默吞掉 |
| 单元切换 | 左栏 `_Sidebar` + `UnitRow` | **无** | 283 节平铺一条长列表 |
| 筛选（全部/待处理/失败）/ 搜索 | 中栏 `_FilterChip` + 搜索框 | **无** | 长列表里找不到失败项 |
| 行详情（题数、题型、答案） | 右栏 `_CurrentCard` + 结果 | **点了没反应** | 死交互 |
| 重新扫描 / 切换课程 | 账号胶囊菜单（227、274 行） | **无**（菜单只有退出登录） | 扫描为空时**无法恢复** |
| 单节重试 | 失败行可展开重试 | **无** | 失败只能整体重跑 |
| 下拉刷新 | — | **无** | 没有"重新扫一遍"的直觉路径 |
| 运行中改设置 | 只读 | **可写** | 与桌面语义不一致 |

关键点：`AppState` 里 `setUnit()` `setFilter()` `setQuery()` `remainingEstimate` `failedCount` `select()` 全都写好了，**移动端一个都没接**。这是一次"少接了几根线"，不是重写。

## 3. 问题清单（按影响排序）

### P0-1 运行中看不到当前节与倒计时

- **位置**：`_MobileShell.build`（1160–1289 行）
- **现象**：点「开始」后，屏幕上只有列表在变，没有任何"当前跑到哪、还剩多久"。倒计时只存在于桌面 `_CurrentCard`，手机端只能开日志抽屉猜。
- **依据**：一节等待 300–420s，一次跑 75 节；用户的实际行为是"隔十分钟瞄一眼"。
- **建议**：列表顶部插入吸顶「运行卡」（见 §5.2），运行中常驻，非运行态替换为"下一节预览"。
- **验收**：开始后 1 秒内，首屏可见 `mm:ss` 倒计时、心跳计数、第 n/总 队列位置。

### P0-2 点击队列行是死交互

- **位置**：`LessonTile` 的 `onTap: () => state.select(lesson.scoid)`（1235 行）
- **现象**：`select()` 只改 `selectedScoid`，移动端没有任何消费者，行只是左边多一条 2px 强调线。用户以为没点中。
- **依据**：桌面同一点击会切换右栏详情；移动端漏了对应容器。
- **建议**：点击弹出「小节详情」底部抽屉（§5.6），抽屉里直接给「只跑这一节」。
- **验收**：点任意一行，300ms 内看到小节名、scoid、题数、题型分布、状态。

### P0-3 扫描失败/结果为空后没有恢复入口

- **位置**：`_MobileShell` 的 `PopupMenuButton`（1188–1212 行）只有一个「退出登录」
- **现象**：`candidates.isEmpty` 时底部「开始」永久灰着，`_EmptyHint` 类只存在于桌面；账号菜单里没有"重新扫描"。用户唯一出路是退出登录再重登（要重新粘 Cookie）。
- **建议**：账号菜单补「重新扫描」「切换课程」；空态给一张带主按钮的卡片（§5.7）。
- **验收**：在 0 待处理状态下，首屏能直接点「重新扫描」并看到进度提示。

### P0-4 283 节一条平铺列表，没有单元分组

- **位置**：`ListView.builder`（1226–1238 行）
- **现象**：`visibleLessons` 未设 `selectedUnit`，8 个单元 283 行首尾相接；行只显示 `location` 单行省略，同一单元里 `Warm-up / Conversation` 这类短名完全分不清属于哪个单元。
- **建议**：按 `unitIndex` 插单元分组头（吸顶），并在 AppBar 下加一条横向「单元条」（§5.3）。无需新依赖，用 `CustomScrollView + SliverPersistentHeader`。
- **验收**：滚动时组头吸顶；单元条可一键筛到某单元，筛选后行数变化可见。

### P0-5 登录流程没有为手机设计

- **位置**：`_showLoginDialog`（1362–1444 行）
- **现象**（截图为证）：
  1. 要求用户"在浏览器登录、从开发者工具复制 Cookie"——手机上做不到开 devtools；
  2. 粘贴后**整段 Cookie 明文回显**在 `maxLines: 5` 的输入框里，截图即泄密（这次已经泄了一次）；
  3. 没有「从剪贴板读取」按钮，用户得长按输入框 → 粘贴，跨应用来回；
  4. 报错文案是底层异常直出：`网络连接失败：Failed host lookup: 'welearn.sflep.com'`，而真实原因是 release APK 缺 INTERNET 权限（另见提交说明）。用户会误以为是自己网络问题。
- **建议**：
  - 加「从剪贴板读取」主按钮，读到的 Cookie **不回显，只显示摘要**「已读取 4 项 · area、acw_tc、.AspNet.Cookies…」；
  - 说明文案改成手机可执行的两步（"手机浏览器登录 → 用书签/插件导出 Cookie"），或直接指向桌面版取 Cookie；
  - 错误分层：无网络 / 无权限 / Cookie 失效 分别给不同文案 + 下一步动作。
- **验收**：全程不出现完整 Cookie 明文；点一次按钮即可完成粘贴。

### P1-1 底栏信息不足，主按钮禁用无解释

- **位置**：底栏（1245–1287 行）
- **现象**：只有 `已完成 · 待处理` 和进度条；没有失败数、没有剩余时间；「开始」在 `candidates.isEmpty` 时置灰但不说明原因。
- **建议**：改成三段式（进度条 / 统计 / 主按钮），统计含 `失败 n`、`剩余约 xx`；禁用时按钮下方 11px 说明「队列为空，先重新扫描」。

### P1-2 日志抽屉是排查唯一入口，但不可用

- **位置**：`_showLogsSheet`（1291–1315 行）
- **现象**：`DraggableScrollableSheet` 没有拖拽手柄，用户不知道能拖；没有级别筛选、没有"复制日志"、没有自动滚到最新。
- **建议**：加 40×4 圆角手柄、顶部一行「全部/心跳/错误」筛选 + 复制按钮；默认滚到底部。

### P1-3 设置对话框在手机上不合适

- **位置**：`_showSettings`（1446–1535 行）
- **现象**：`AlertDialog` + `SizedBox(width: 420)`，390 宽屏上是硬挤的双滑块；运行中也能改并保存，与设计文档"运行中只读"矛盾。
- **建议**：改底部抽屉 + 分组（等待 / 正确率 / 间隔 / 跳过口语），运行中整块禁用并说明「运行中不可修改」。

### P1-4 未登录首屏只有一个按钮

- **位置**：1239–1244 行
- **现象**：空屏正中一颗「登录」，没有任何说明这是什么、要点什么；`WeLearn 助手` 顶栏副标题"未登录"。
- **建议**：空态卡：标题「还没有登录」+ 一句解释 + 主按钮「粘贴 Cookie 登录」+ 次按钮「怎么获取 Cookie」（展开说明或跳到桌面版说明）。

### P2 视觉与细节

| 位置 | 问题 | 建议 |
| --- | --- | --- |
| AppBar 标题 | 课程名 14px + 副标题 11px，手机上偏小偏弱 | 标题 16px/600，副标题 11.5px；课程名过长走两行省略 |
| `LessonTile` | 固定 56 高、`location` 单行省略；无右侧箭头 | 移动端改 64 高、两行省略；末尾加 12px 的 `Icons.chevron_right` 暗示可点 |
| 触控目标 | 状态胶囊/图标按钮按桌面 32 高定 | 移动端图标按钮 ≥44，行内可点区整行 |
| 角标数字 | `已完成 · 待处理` 用中文分隔符，与等宽数字混排 | 统一 `tabular` 数字；失败数用 `danger` 色点 + 文字，不只靠颜色 |
| 状态颜色 | 已符合"颜色不单独承载语义" | 保持 `StatusDot` 的形状双编码 |

## 6. 交互与状态规则

1. **运行中列表不锁死**：仍可滚动、点行看详情；但「开始」变「停止」，设置只读，单元条可切（只影响浏览，不影响队列）。
2. **自动定位**：每切换一节，列表自动滚到当前节并高亮 1.2s；用户手动滚动后 5s 内不再自动滚（避免抢控制权）。
3. **停止语义**：点「停止」弹确认「当前节不会提交，已完成的节保留」，确认后底部按钮变「开始」。
4. **失败可查**：失败行点开抽屉，底部给「重试本节」（P1，需要 runner 支持单节入口）。
5. **下拉刷新**：非运行态下拉 → `loadCourse(rescan: true)`，运行态禁用手势并提示「运行中不能重新扫描」。
6. **返回键**：抽屉/对话框优先关闭；主页返回退到后台，不退出登录。
7. **旋转/分屏**：≥600 宽时退回双栏（左列表右详情），复用桌面 `_CurrentCard`。

## 7. Flutter 实现方案

### 7.1 文件拆分（`shell.dart` 已 1594 行，先拆再改）

```
lib/ui/
├── shell.dart            // 只留平台分发：宽<600 → MobileShell
├── desktop/              // 平移现有 _DesktopShell/_Sidebar/_QueuePane/_RunPane
├── mobile/
│   ├── mobile_shell.dart       // 骨架 + AppBar + 底栏
│   ├── run_card.dart           // §5.2，复用 desktop 的 CurrentCard 逻辑（抽公共）
│   ├── unit_strip.dart         // §5.3
│   ├── lesson_list.dart        // 分组列表 + sticky header
│   └── sheets.dart             // 详情 / 日志 / 设置
├── widgets.dart          // StatusDot / StatusPill / ThinBar / LessonTile 共用
└── dialogs/              // 登录、退出确认
```

### 7.2 只接线，不改引擎

移动端需要补的调用，全部已有实现：

| 缺口 | 调用 |
| --- | --- |
| 单元切换 | `state.setUnit(i)`（`app_state.dart:97`） |
| 筛选/搜索 | `state.setFilter(f)` / `state.setQuery(q)`（392、397 行） |
| 行详情 | `state.select(scoid)` + `state.selectedLesson`（387、402 行） |
| 剩余时间 | `state.remainingEstimate`（126 行） |
| 失败/跳过数 | `state.failedCount` / `skippedCount`（112–115 行） |
| 重新扫描 | `state.loadCourse(cid, rescan: true)`（246 行） |
